# codex-touch v0.3.0

Version 0.3.0 makes the “Resume a previous session” screen usable by touch and extends touch to menus, dialogs, completion lists, and navigation hints. It remains pinned to Codex 0.169.0 and builds entirely on a phone in Debian ARM64 with Termux as the terminal.

## Highlights

- Select and open sessions in resume/fork pickers; tap filters, sorting, active/archived status, density, preview, expansion, and cancellation controls. Stable session identity and gesture cancellation prevent stale row activation.
- Use shared list dialogs, settings and multi-select controls, approvals, synchronous questions, MCP forms, provider fields, and startup/setup navigation while retaining original validation and confirmation flows.
- Tap command/file/skill/mention completions. Completion inserts the selected content; submit separately.
- Use floating chord/preset hints, transcript and pager controls, history-search accept/cancel, warnings and analytics hints, shortcut customization, and combined subagent navigation.
- Preserve v0.2.0 asynchronous question, composer, command center, and interruption controls. Dragging, clipping, resizing, stale state, and covered views remain guarded.
- Publish a matching GitHub Release whenever a version update is confirmed, unless explicitly deferred. This policy is recorded in both project conventions and the development guide.

See the [coverage and acceptance record](../picker-touch.md) for the complete inventory.

## Build and run

The target is `aarch64-unknown-linux-gnu` (glibc), verified in Debian chroot with Termux. Install the dependencies and pinned Rust 1.95.0 toolchain using the [phone build guide](../build.md), then:

```sh
git clone --branch v0.3.0 --depth 1 https://github.com/Zircon10086/codex-touch.git
cd codex-touch
bash scripts/check.sh
bash scripts/build-touch.sh
bash scripts/run-touch.sh resume
```

The default output is `~/codex-touch-build/packages/touch-pickers-0.169.0`. Existing packages are never overwritten; set `CODEX_TOUCH_PACKAGE` to a new path for another build. The launcher enables `CODEX_TOUCH=1` and preserves HOME/CODEX_HOME, so normal launches share configuration and sessions with regular Codex under the same Linux user.

The upstream CLI still reports `codex-cli 0.169.0`; **0.3.0** identifies the codex-touch adaptation. The development phone already uses the accepted package through its pinned `crcodex` launcher. Publishing this version does not require rebuilding that identical binary.

## Assets

- `codex-touch-0.3.0-source.tar.gz`: repository source, cumulative patch, scripts, licenses, and bilingual documentation, without Git metadata, credentials, or build caches.
- `SHA256SUMS`: SHA-256 for the named source archive.

Download both files into one directory and run `sha256sum -c SHA256SUMS`. GitHub also provides automatic source archives; their different bytes are not covered by this checksum file. No prebuilt client is attached. Build scripts work from extracted source; repository checks additionally require a Git checkout.

## Validation

The included Rust patch passed 1,297 distinct regressions across 43 registered filters, package/helper and app-server checks, a loopback model/tool round trip, and default-daemon TUI checks. The extended SGR mouse PTY passed in 49.8 seconds, including resume filtering/preview/opening, direct startup resume, completion, modal cancellation, shortcut customization, and terminal restoration. The pinned daily launcher separately passed the extended PTY in 55.0 seconds with inherited `CODEX_TOUCH` removed.

The user confirmed on-device testing on 2026-11-18. This release changes versioning, documentation, and release-note checks; its Rust patch and installed binary are unchanged from the accepted build. The Rust and PTY results above are the recorded feature/deployment validation, not new runs performed for this release. Release checks verify repository consistency, bilingual links, exact patch matching, archive contents, and published asset integrity.

## Known limits

- Default full-screen TUI only; `--no-alt-screen` is outside supported touch coverage.
- Open the Android keyboard manually; automatic IME display is not implemented.
- Some main-help transcript entries are reference text; open the transcript to use its active controls. Cloud/gateway setup forms use the touch navigation bar to move between fields.
- The asynchronous answer-editor newline convenience and the previously reported multi-question stall remain follow-up work.
- Other Termux channels, proot, other architectures, and every external provider flow have not received equivalent validation.
