# 第一阶段：异步问答触摸

开发基于 `upstream.json` 固定的 Codex 0.169.0，点击路由适用于默认全屏终端模式；`--no-alt-screen` 的内联模式不在本阶段范围。补丁在 `src/async-question-touch.patch`；通过 `CODEX_TOUCH=1` 开启。版本号仍是框架基线 0.1.0，当前功能属于未发布开发版。

## 行为与边界

- 点按底部折叠的问题提示展开问答，展开期间保留终端鼠标上报。
- 点选完整显示的命名选项，经过原版发送或排队策略提交；接受后才移除问题。
- 点 Other 进入原版自由编辑器；已有文字可点按移动光标，支持键盘输入和粘贴。
- 可点击完整显示的底部 submit、skip、前后切换提示，复用当前单键快捷键。用户自定义的两段快捷键提示仍需键盘操作。
- 问答区域内滚轮浏览选项，不提交。拖动、尺寸变化、失焦、键盘输入、弹层覆盖及换题会取消未完成点按。
- 模型选项必须完整显示才能提交；不通过点击绕过原版可见性和发送权限检查。

本阶段只适配异步问答。普通同步问答弹层、自动弹出 Android 软键盘不在此补丁范围。输入文字仍需手动打开软键盘。开启后，展开的问答区域由 Codex 接收鼠标事件，终端对该区域的链接和选择行为可能与原版不同。

## 手机本地构建与运行

在 Debian chroot 中运行（不是直接使用 Termux 的 Android 编译器）：

```sh
cd /storage/emulated/0/Agent/codex-touch
bash scripts/build-touch.sh
bash scripts/run-touch.sh
```

构建入口会验证上游提交，规范化已知锁文件，再应用并核对精确补丁。未知改动会使构建停止；已构建的基线包不会被覆盖。默认单任务、dev-small、LLD，复用 `~/codex-touch-build/target`。独立产物默认位于 `~/codex-touch-build/packages/touch-0.169.0`，包含上游辅助程序和 `touch-build.json`。

`CODEX_TOUCH_BUILD_DIR` 可指定 Linux 构建根目录，`CODEX_TOUCH_PACKAGE` 可指定新产物目录。现有包不自动覆盖。`run-touch.sh` 只为子进程开启开关，不修改日用启动器、配置或全局环境；直接运行同包 `bin/codex` 且不设置 `CODEX_TOUCH=1`，可对照原版鼠标行为。

独立程序包不等于隔离会话：`run-touch.sh` 不改变 HOME 或 CODEX_HOME；在与 `crcodex` 相同的 chroot 中，默认共用 `/home/developer/.codex` 的配置与会话记录。自动化验收则显式使用临时 HOME/CODEX_HOME。

持续构建需要控制手机温度和并发、保持 Termux 唤醒。构建脚本使用低优先级与单个 Cargo 任务；本次实测另使用构建目录中的资源监视器，每 2 秒采样电池温度，44°C 暂停、42.5°C 恢复进程组。最初 41.5°C 的恢复阈值在充电期间导致较长等待，已调整。尝试过 `taskset` 限制 CPU，但实测 Android 随后重新设置了进程亲和性，也曾因 CPU 0 不在当时允许集合中而启动失败，最终移除了该参数。因此不能把此设置当作持续限核的保证。不要将基线阶段的耗时当作此次测试构建耗时。

## 自动验收

```sh
bash scripts/check.sh
bash scripts/check.sh --upstream-source "$HOME/codex-touch-build/upstream" --rust-tests
bash scripts/check.sh --touch-package "$HOME/codex-touch-build/packages/touch-0.169.0"
```

- 基础检查：补丁语法、Python/Shell、仓库格式、既有锁文件与 IME 探针回归。
- Rust：上游问答相关测试、共享行渲染器和普通问答弹层回归；新增用例检查绘制坐标、中文换行、裁剪、滑动、过期点按、重复松手、Other、自由输入、窄屏和鼠标捕获开关。
- 程序包：已有完整工具回合回归；另用独立 HOME/CODEX_HOME、本机 HTTP 假模型和 PTY，发送真实 SGR 鼠标序列，检查摘要展开、保留捕获、缩屏、选项、Other、自由输入、底部提交、答案送达和退出恢复。

PTY 的屏幕解码器只服务合成测试，不能证明 Android 实际触摸或软键盘行为。原版包对照已停在“Summary did not expand”，确认测试覆盖原始故障。

## 真机验收（2026-11-17：主要路径通过）

用户在手机 Termux 中完成测试并反馈高度可用，随后授权核对测试会话。会话记录包含 16 份不同问题的结构化回复，以及跳过等操作的文字反馈；其中部分回复是问题报告，不能把 16 份回复全部计为通过。以下只记录测试结论，不收录原始会话、题目或会话标识。

| 测试范围 | 结果与依据 |
| --- | --- |
| 问题打开、命名选项点答 | 用户实测正常，对应答案成功传回 |
| 长选项换行、第八项选择 | 目标选项成功传回，用户未报告选错 |
| 中文自由输入、光标编辑、Other | 自由回答和中间插入后的内容成功传回 |
| 滑动误提交 | 用户确认此前第二项为主动点击，没有发生误提交 |
| 跳过 | 用户明确确认点按底部提示后成功跳过 |
| 收起/展开与草稿保留 | 用户确认重新打开后草稿保留 |
| Other 返回预设选项 | 用户确认能够返回并提交预设答案 |
| 手动换行 | 未通过：当前输入方式缺少可用的组合键入口，Enter 直接提交 |
| 跨题导航 | 未验证：用户将 Shift 提示理解为必须使用实体修饰键，没有完成切题测试 |
| 多题并存 | 曾报告卡住，原因未确认；改成逐题发送后顺利完成 |
| 普通同步问答 | 未进入界面：Default 模式拒绝接口调用，尚未测到触摸行为 |

会话还报告工作结束后剩余问题无法继续操作。源码核对显示，原版在回合结束时回收未提交的文字草稿并清除待答题；这是现有问答生命周期，不能据此归因为触摸故障。后续交互验收应保持回合运行，等用户答完再结束；暂按一次一道题进行，另单独复现多题问题。

导航提示的可发现性需要改善：当前实现已给完整显示的 `prev question`、`next question` 等单键快捷键提示添加点击区域，包括带 Shift 的组合键，点按时无需实际按 Shift。但这不代表本轮跨题点按已经通过真机验收；窄屏裁剪与用户未识别入口等情况仍需区分。建议下一步增加清晰的换行与导航触摸入口，并复现多题卡住，再扩大到普通同步问答和 IME。

折叠/展开屏幕、失焦后恢复、正常及异常退出后的真机终端恢复，没有足够的本轮记录，仍待补验。自动化的尺寸变化和退出恢复验证保留为独立证据；输入法自动弹出仍未实现。
