# 设计起点

## 目标与当前范围

让用户在 Termux 中使用 Codex 时，能够以触摸完成需要的交互。首个功能的具体操作、手势与界面范围尚待确定。

0.1.0 仅建立开发框架。仓库尚未选择实现语言，尚未接入终端输入，也未修改 Termux、Codex 或其启动器。

## 实现前需要验证

1. 明确首个交互：用户触摸哪里、期望触发什么动作、怎样判断成功。
2. 检查目标版本的 Termux 与 Codex 代码和接口，确认触摸如何转成终端事件、哪些事件可被 Codex 接收。
3. 在实际启动方式中验证输入、输出、窗口尺寸及信号的传递，再比较直接利用现有能力、适配输入或修改上游的成本。
4. 根据验证结果选择语言和最小实现，记录依赖、兼容版本与限制。

现有 `termux-run` 桥用于非交互工具调用，没有 PTY；不能把通过它运行命令视为交互终端验证。

## 首个功能的验收要求

- 将触摸动作与预期结果写成可复现步骤。
- 键盘输入、终端尺寸变化、正常退出和中断行为有明确验证记录。
- 若组件改变终端模式，退出或异常时能够恢复。
- 涉及输入转换时，用合成事件覆盖正常、边界和无效输入。
- 自动化检查与需要手机交互的人工验收分别记录，尚未执行的验收明确标注。

确认首个功能后，再在这里补充实际数据流和实现决定。
